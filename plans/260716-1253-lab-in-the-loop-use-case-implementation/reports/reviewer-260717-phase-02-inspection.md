- `apps/canvus-mcp/canvus_mcp/experiments.py`: `ExpMarkers.closed: str = "[EXP:Closed]"` added; `_is_closed(w, m)` added (title-prefix match, no `widget_type` restriction, mirrors `_is_robot`); `scan_workflow()` now classifies a `closeds` list (checked after `_is_result`, before `_is_robot`) and returns it as `"closeds": [_brief(...) ...]` in the snapshot. `apps/canvus-mcp/canvus_mcp/config.py` adds `mcp_exp_closed_marker` (default `"[EXP:Closed]"`); `apps/canvus-mcp/canvus_mcp/tools/experiments.py`'s `_markers()` wires it through, and the tool docstring documents the new bucket.

- `apps/lab-agent/lab_agent/durable_writes.py::write_closed_node_durable` now tags the closed note's title the same way setup/result notes are tagged, and its `probe()` closure calls `canvas_probe.probe_note_by_tag(mcp, canvas_id=canvas_id, bucket="closeds", idempotency_key=key)` instead of the removed `probe_closed_note`.
- **Independent repro** (`/tmp/repro2_closed_note_no_duplicate.py`, outside the repo, not reusing `tests/fakes.py` — a local `MinimalMCP` stub): prepared the intent, let the canvas write for the closed note land, closed the `StateStore` *before* `mark_executed`/`mark_reconciled` ran (simulating the exact documented crash boundary), then opened a fresh `StateStore` against the same on-disk file and called `write_closed_node_durable` again (simulating restart). - Also cross-checked the new regression test `test_closed_note_crash_before_connector_recovers_without_duplicate_across_restart` (`tests/test_durable_recovery_integration.py:134-215`): it drives the same boundary through the real `process_once`/`watch` path (not just `durable_writes` directly), across **two** successive fresh `StateStore`s, and additionally asserts the `workflow_attempts` row reaches `COMPLETED` exactly once and a second restart does not re-run the (already-completed) attempt (`counts["loops"] == 0`). ### Re-Verification of Prior Critical Issue #2 — Silent phantom-success on MCP `isError=True`

**Status: FIXED. Independently confirmed.**

- `apps/lab-agent/lab_agent/nodes.py` adds `MCPToolError(Exception)`, `_parse_checked()` (raises on malformed JSON, non-dict response, or an explicit `"error"` key), `_require_id()` (raises on a missing or empty `"id"`), and `_call_checked()` (`await mcp.call_tool(...)` then `_require_id(_parse_checked(...))`). `create_node()` and `connect()` now both call `_call_checked()` instead of the prior lenient `_call_json()` + `res.get("id", "") or ""` pattern. `read_note_text()` correctly keeps using the lenient `_call_json()` — a read path where "nothing found" is a legitimate, non-error outcome, not a write path where a phantom id is dangerous.
- `apps/lab-agent/lab_agent/mcp_client.py::call_tool` is unchanged (still converts `isError=True` into a non-raising `json.dumps({"error": ...})`) — correct, since the fix belongs at the write call sites, not the transport layer, and this is exactly where it landed.
- `apps/lab-agent/lab_agent/recovery.py::reconcile_or_execute` is **unchanged** — no change was needed there; its existing `except Exception` around `execute()` already calls `mark_failed` and re-raises. The fix only needed `execute()`'s callees (`nodes.py`) to actually raise instead of silently returning `""`, and that dependency now holds.
- **Independent repro** (`/tmp/repro2_write_error_fails_closed.py`, outside the repo, a local `RealisticErrorMCP` stub — not `tests/fakes.py`): first `create_note` call returns `json.dumps({"error": "canvas not found"})` (the exact non-raising shape real `MCPClient.call_tool` returns on `isError=True`); second call succeeds. Ran `durable_writes.write_setup_node_durable()` end-to-end against a real `StateStore`. Result:
  ```
  Attempt 1: raised MCPToolError = MCPToolError('create_note failed: canvas not found')
  Attempt 1: setup_id local var (if no exception) = ''
  Attempt 1: intent status = failed, external_id = None
  Attempt 2 (retry): setup_id = 'note1'
  Total setup notes on canvas: 1 ['note1']
  Attempt 2: intent status = reconciled, external_id = 'note1'
  FIX CONFIRMED: MCP error payload fails closed (intent FAILED, no phantom id, no note), and the next retry succeeds exactly once with no duplicate.
  ```
  Matches coordinator requirement #2 verbatim: the intent/attempt is failed/retryable, never reconciled/completed with an empty id, and the next due retry succeeds exactly once.
- Also independently confirmed (via `tests/test_nodes.py`, read in full, 19 tests) that `create_node`/`connect` raise `MCPToolError` for all four required fail-closed shapes: an explicit `"error"` key, malformed (non-parseable) JSON, a non-object response (e.g. a JSON array/string), and a missing **or** empty `"id"` — via a local `_RawMCP` stub distinct from `FakeMCP`. `read_note_text` is confirmed to stay lenient (never raises) across the same failure shapes.
- Also cross-checked `tests/test_durable_recovery_integration.py:229-337`'s two new regressions (`create_note` error payload during setup-note write; `create_connector` error payload during the idea→setup edge write): both confirm the intent is `FAILED` (never `RECONCILED` with an empty/phantom id), the attempt is `FAILED` (never `COMPLETED`), no phantom note/edge is created, and the next due retry (deterministic `rng=lambda: 0.0`) succeeds exactly once with no duplicate — including the connector-specific case where the already-reconciled setup note is correctly *not* re-created (no second `create_note` call) on retry.
